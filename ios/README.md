# LIOS iOS app

The iPhone half of LIOS: a host app, a share extension and a notification service extension.

## Layout

- `LIOSKit/` — a Swift package holding everything that builds and tests without an app host:
  the wire models, AES-256-GCM sealing, framing, pairing QR handling, the relay HTTP client, the
  Keychain-backed credential store, local history and the in-app log ring buffer. Builds and
  tests on Linux; only the parts guarded by `#if canImport(Security)` (the Keychain store) or
  `#if canImport(FoundationNetworking)` need an Apple platform or a Linux Foundation shim.
- `LIOS/` — the host app target: SwiftUI views, push registration, and the notification-tap
  receive path.
- `LIOSShare/` — the share extension. Registered for text, URLs, images and files; uploads
  directly from its own process rather than staging into a shared container.
- `LIOSNotify/` — the notification service extension. Decrypts a small sealed preview attached
  to the push and rewrites the banner; never downloads the item's own payload.
- `LIOS.xcodeproj/` — hand-written project file, one target per component above, each with a
  `PBXFileSystemSynchronizedRootGroup` so adding or removing a source file needs no project edit.
- `fastlane/` — signing and TestFlight upload, shared between a local machine and CI.
- `Tooling/` — `parse-swift.sh` (syntax-checks the app-only Swift, since the app target compiles
  nowhere but macOS) and `swift6-lint.py` (regex heuristics for Swift 6 / SwiftUI shapes that
  only fail on a real build).

## No App Group

Apple's App Store Connect API has no endpoint for creating an App Group
(`GET /v1/appGroups` returns 404), and creating one by hand was not done for this project. Every
place that would normally use a shared container instead uses a Keychain access group
(`$(AppIdentifierPrefix)com.frederikberg.lios`, shared by all three targets), which needs only a
shared team:

- The share extension uploads the sealed item directly to the relay from its own process,
  instead of staging it into a shared container for the host app to pick up later. This caps
  what it can send: roughly 80 MB, conservative against the extension's undocumented memory
  ceiling.
- The notification service extension reads the group key from the shared Keychain item to
  decrypt the push's attached preview, and nothing else.

## Building and testing

```
swift build --package-path LIOSKit --build-tests
swift test --package-path LIOSKit --skip-build
bash Tooling/parse-swift.sh
python3 Tooling/swift6-lint.py
```

The app target, the share extension and the notification service extension all compile only on
macOS — a Mac build is what actually proves them.

## Wire format

`LIOSKit`'s crypto, framing and pairing code is a Swift mirror of the `lios_protocol` Python
package: the same AES-256-GCM blob layout (`nonce || ciphertext || tag`), the same
length-prefixed metadata frame, and the same pairing QR payload shape. `LIOSKitTests` includes
fixtures generated by running `lios_protocol` directly, so a change to either side that breaks
the correspondence fails a test rather than a live pairing.
